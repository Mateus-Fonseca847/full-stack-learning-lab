# Aula 19 — Wi-Fi (IEEE 802.11): acesso ao meio, quadro e economia de energia

> ⚠️ **Sem slides:** conteúdo montado a partir da **lista de Wi-Fi** da P2 e de conhecimento geral. Lista: [`listas/lista-19.md`](../listas/lista-19.md). Anterior: [aula 18](18-wifi-fundamentos-fisicos.md).

## 1. Problemas do meio sem fio

- **Estação escondida (hidden station):** A e C **alcançam B**, mas **não se ouvem** entre si. Ambas acham o canal livre, transmitem e **colidem em B**.
- **Estação exposta (exposed station):** B transmite para A; C **ouve B** e se **abstém** de transmitir para D, embora **não interferiria** em A. Desperdício de capacidade.

Além disso, o rádio **não consegue detectar colisão** (não ouve enquanto transmite) → **CSMA/CA** em vez de CSMA/CD. A solução parcial para a estação escondida é o handshake **RTS/CTS**.

## 2. Funções de coordenação

| | **DCF** (Distributed Coordination Function) | **PCF** (Point Coordination Function) |
|---|---|---|
| Controle | **distribuído**, por **disputa** | **centralizado**: o AP **consulta (polling)** cada estação |
| Base | **CSMA/CA** | lista de consulta (polling list) |
| Obrigatório? | **Sim** (é o modo padrão) | Opcional (raramente implementado) |
| Período | **CP** (contention period) | **CFP** (contention-free period) |

**Os dois podem coexistir na mesma rede:** alternam no tempo dentro do **superquadro**.

### Superquadro (superframe)
Intervalo entre dois **beacons**:
```
|Beacon| ←── CFP (PCF, sem disputa) ──→|CF-End|←── CP (DCF, com disputa) ──→| próximo Beacon
```
O beacon abre o superquadro e anuncia a duração do CFP; o CFP termina com um **CF-End**; o resto do tempo é CP.

### Polling (PCF)
No CFP, o AP envia **CF-Poll** às estações da lista, uma de cada vez; a estação consultada responde com dados (ou nulo). **Elimina colisões** e garante atraso limitado.

## 3. CSMA/CA (DCF)

1. Estação com quadro **escuta o canal**. Se livre por um **DIFS**, **sorteia um backoff** (nº de *slots* aleatório dentro da janela **CW**).
2. Decrementa o contador **só enquanto o canal está livre**; se ficar ocupado, **congela** e retoma depois.
3. Contador = 0 → **transmite**.
4. O receptor responde com **ACK** após um **SIFS**.
5. **Sem ACK** → assume colisão/erro → **dobra a CW** (backoff exponencial) e tenta de novo.

**Opcional — RTS/CTS:** origem envia **RTS**, destino responde **CTS**; ambos trazem o campo **Duração**, e quem escuta ajusta o **NAV** (carrier sense virtual), ficando quieto. Resolve a **estação escondida** (a que ouve o CTS fica calada).

### Espaçamentos entre quadros (IFS) — quanto menor, mais prioridade

| IFS | Valor (ex.: 802.11a, 5 GHz) | Função |
|---|---|---|
| **SIFS** (Short) | 16 µs (10 µs em 2,4 GHz) | **maior prioridade**: separa quadros de **um mesmo diálogo** (**ACK, CTS**, fragmentos seguintes, resposta de poll) |
| **PIFS** (PCF) | SIFS + 1 slot | usado pelo **AP** para tomar o canal antes das estações DCF (**iniciar o CFP**, enviar polls) |
| **DIFS** (DCF) | SIFS + 2 slots | espera **antes de iniciar** uma transmissão normal por disputa |
| **EIFS** (Extended) | SIFS + tempo do ACK + DIFS | usado **depois de receber um quadro com erro** (não deu para ler o NAV); espera mais para **não atropelar** o ACK de um diálogo que a estação não entendeu; **menor prioridade** |

Ordem: **SIFS < PIFS < DIFS < EIFS**.

## 4. Fragmentação e agregação

**Fragmentação:** como o meio é **ruidoso**, quadros menores têm **maior chance de chegar sem erro** e, se perdidos, **custam menos** para retransmitir. O quadro é dividido em fragmentos conforme um **limiar de fragmentação**.

**Envio dos fragmentos:** a estação envia o fragmento 1 → recebe **ACK após SIFS** → envia o fragmento 2 após SIFS → ... Como só se usa **SIFS** entre eles, a estação **mantém o canal** (rajada) até o último fragmento. O campo **Duração** de cada fragmento reserva o tempo do **próximo fragmento + ACK**; o bit **More Fragments** e o **número de fragmento** (no Controle de Sequência) permitem remontar.

**Agregação (A-MSDU, desde o 802.11n):** o oposto — **junta vários pacotes** num **único quadro** quando o canal é bom, para reduzir **overhead** (um só cabeçalho PHY/MAC, um backoff, um ACK). Aumenta a **eficiência**.

## 5. O quadro 802.11

```
┌─────────┬─────────┬────┬────┬────┬─────────┬────┬──────────────┬─────┐
│ Frame   │Duração/ │ A1 │ A2 │ A3 │Controle │ A4 │ Corpo        │ FCS │
│ Control │   ID    │    │    │    │  de Seq │    │ (0–2312 B)   │     │
│  2 B    │  2 B    │6 B │6 B │6 B │  2 B    │6 B │              │ 4 B │
└─────────┴─────────┴────┴────┴────┴─────────┴────┴──────────────┴─────┘
                                               (A4 só em AP↔AP)
```

### Campo Controle de Quadro (Frame Control, 16 bits)
| Campos | Função |
|---|---|
| **Versão do protocolo** (2 bits) | versão do protocolo MAC (hoje **0**) |
| **Tipo** (2) e **Subtipo** (4) | **00 gerenciamento**, **01 controle**, **10 dados** + qual quadro é |
| **To DS / From DS** | indica o **sentido** em relação ao sistema de distribuição (AP) |
| **More Frag** | há mais fragmentos |
| **Retry** | é retransmissão |
| **Power Mgmt** | estação vai entrar em **economia de energia** |
| **More Data** | AP tem mais quadros em buffer para a estação |
| **Protected Frame** | corpo cifrado |
| **Order** | ordem estrita |

**Por que existe esse campo?** Para o receptor saber **que tipo de quadro é** (e como interpretar o resto), o sentido de envio e os modos de operação (fragmentos, energia, criptografia).

**Como um equipamento identifica a "versão" 802.11?** O campo **Versão do protocolo** só identifica a versão do **MAC** (sempre 0). As versões **a/b/g/n/ac/ax** são distinguidas na **camada física** (frequência/preâmbulo PLCP) e nas **capacidades anunciadas** nos beacons e probe responses (taxas suportadas, elementos HT/VHT/HE).

### Campo Duração
Tempo (µs) em que o meio ficará **ocupado** depois deste quadro. As demais estações o usam para configurar o **NAV** (carrier sense virtual) e **ficam quietas**. Ex.: num **RTS**, a duração cobre **CTS + dados + ACK + 3 SIFS**; assim quem ouve só o RTS já sabe quanto tempo calar. (No PS-Poll o campo carrega o **AID** da estação.)

### Por que 4 campos de endereço?
Em redes com **AP**, o quadro tem endereços **fim a fim** (origem e destino reais) e endereços **do salto de rádio** (quem transmite e quem recebe agora). Eles dependem de **To DS/From DS**:

| To DS | From DS | Situação | A1 | A2 | A3 | A4 |
|---|---|---|---|---|---|---|
| 0 | 0 | **ad hoc** (direto) / controle | DA | SA | BSSID | — |
| 1 | 0 | **estação → AP** | BSSID (AP) | SA | DA | — |
| 0 | 1 | **AP → estação** | DA | BSSID (AP) | SA | — |
| 1 | 1 | **AP → AP** (ponte sem fio / WDS) | RA | TA | DA | **SA** |

(DA = destino, SA = origem, RA = receptor imediato, TA = transmissor imediato.) O A4 só aparece quando **dois APs** se comunicam por rádio.

**Como saber se o emissor é um AP?** Pelos bits **To DS / From DS**: **From DS = 1 e To DS = 0** → veio de um AP (e o endereço 2 é o BSSID).

### Ad hoc × estruturada
- **Ad hoc (IBSS):** estações **falam diretamente**, **sem AP**, rede temporária.
- **Estruturada (infraestrutura, BSS/ESS):** estações falam **através de um AP**, que dá acesso ao **sistema de distribuição** (rede cabeada/Internet).

### Tipos de quadro
- **Gerenciamento:** beacon, probe request/response, authentication, association/reassociation, disassociation.
- **Controle:** **RTS, CTS, ACK, PS-Poll, CF-End**, Block Ack.
- **Dados:** carregam o payload (inclui variantes com QoS e nulos).

**Principais quadros de controle:**
| Quadro | Tipo/Subtipo | Função | Campos |
|---|---|---|---|
| **RTS** | 01 / 1011 | pede reserva do canal | FC, Duração, **RA, TA**, FCS (20 B) |
| **CTS** | 01 / 1100 | autoriza e reserva | FC, Duração, **RA**, FCS (14 B) |
| **ACK** | 01 / 1101 | confirma recepção | FC, Duração, RA, FCS (14 B) |
| **PS-Poll** | 01 / 1010 | estação acorda e pede quadros em buffer | AID, BSSID, TA |
| **CF-End** | 01 / 1110 | fim do período sem disputa | — |

**RTS ou CTS?** Os dois têm **Tipo = 01 (controle)**; diferenciam-se pelo **Subtipo** (RTS = 1011, CTS = 1100) e pelo tamanho (RTS tem 2 endereços; CTS só o RA). *(Na lista aparece "RTC": é RTS.)*

### Beacon (baliza)
Quadro de **gerenciamento enviado periodicamente pelo AP** (≈ **100 ms**, o "intervalo de beacon"). Carrega **SSID, taxas suportadas, canal, capacidades/segurança, timestamp (sincronização)** e o **TIM** (indicador de tráfego em buffer). **É necessário** para: **sincronização** das estações, **descoberta** da rede (varredura passiva), **economia de energia** (TIM/DTIM) e **delimitar o superquadro** (início do CFP).

## 6. Economia de energia

Estação móvel pode **desligar o rádio** (dormir) para poupar bateria. Ela avisa o AP pelo bit **Power Management** do Controle de Quadro: **1 = vou dormir (economia)**, **0 = ativa**. O AP **guarda em buffer** os quadros destinados a quem dorme.

| Rede | Funcionamento |
|---|---|
| **Estruturada** | o AP **bufferiza** e anuncia no **TIM** do beacon quais estações têm dados; a estação acorda **nos beacons** (a cada *listen interval*/DTIM), lê o TIM e, se tiver dados, os busca |
| **Ad hoc** | **sem AP** para guardar. Após cada beacon há uma janela **ATIM**: quem tem dados para uma estação dormindo manda um **ATIM** avisando; a estação **permanece acordada** até receber, senão volta a dormir |

### Modos em rede estruturada
- **PS-Poll Mode:** a estação acorda no beacon, vê que há dados (bit no TIM) e envia **PS-Poll**; o AP entrega **um quadro** (com **More Data=1** se houver mais); a estação repete o **PS-Poll** até **More Data=0**; depois dorme.
- **APSD (Automatic Power Save Delivery):** entrega **em rajada**, sem um PS-Poll por quadro. **U-APSD:** a estação **dispara** a entrega enviando um quadro de uplink; **S-APSD:** o AP entrega em **intervalos programados**. Bom para **voz (VoIP)** — base do *WMM Power Save*.
- **Wake-on-Wireless (WoWLAN):** não é do 802.11 em si: permite que a **placa sem fio acorde o computador** (suspenso/desligado) ao receber um pacote especial (*magic packet*) ou ao detectar certos eventos, mantendo a NIC em escuta de baixíssimo consumo.

## 7. Associação e varredura

### Para entrar numa rede estruturada
1. **Varredura** (descobrir APs);
2. **Autenticação** (Open System: 2 quadros; Shared Key/WEP: 4 quadros; hoje WPA2/WPA3 tratam a segurança de verdade);
3. **Associação:** estação envia *Association Request*; AP responde com *Association Response* e um **AID** (identificador). A partir daí a estação faz parte do BSS. (Em WPA2: **4-way handshake** em seguida; em redes corporativas, **802.1X**.) Ao mudar de AP: **reassociação** (roaming).

### Varredura ativa × passiva
| | **Passiva** | **Ativa** |
|---|---|---|
| Como | **escuta** cada canal esperando **beacons** | envia **Probe Request** em cada canal; APs respondem com **Probe Response** |
| Velocidade | mais **lenta** (espera ~100 ms por canal) | mais **rápida** |
| Energia / emissão | **gasta menos**, não transmite | transmite → revela a estação |
| Observação | não acha SSID oculto sem beacon | necessária para SSID oculto |

## 8. Segurança e evolução do padrão

**Por que são consideradas mais inseguras?** O meio é **aberto e compartilhado**: qualquer um no alcance pode **escutar (sniffing)**, **injetar quadros** e montar **AP falso (evil twin)** ou **deauth**. Sem barreira física. Evolução da segurança: **WEP** (quebrado) → **WPA/TKIP** → **WPA2/AES-CCMP** → **WPA3/SAE**.

| Padrão | Ano | Faixa | Taxa máx. (teórica) | Tecnologia-chave |
|---|---|---|---|---|
| 802.11 | 1997 | 2,4 GHz | 2 Mbps | FHSS/DSSS/IR |
| **802.11b** | 1999 | 2,4 GHz | 11 Mbps | DSSS/CCK |
| **802.11a** | 1999 | 5 GHz | 54 Mbps | **OFDM** |
| **802.11g** | 2003 | 2,4 GHz | 54 Mbps | OFDM (compatível com b) |
| **802.11n** (Wi-Fi 4) | 2009 | 2,4/5 GHz | 600 Mbps | **MIMO**, 40 MHz, agregação |
| **802.11ac** (Wi-Fi 5) | 2013 | 5 GHz | ~6,9 Gbps | 80/160 MHz, **MU-MIMO**, 256-QAM |
| **802.11ax** (Wi-Fi 6/6E) | 2019–21 | 2,4/5/6 GHz | ~9,6 Gbps | **OFDMA**, 1024-QAM |
| **802.11be** (Wi-Fi 7) | 2024 | 2,4/5/6 GHz | ~46 Gbps | 320 MHz, 4096-QAM, MLO |

## Resumo

- Rádio **não detecta colisão** → **CSMA/CA** (DIFS + backoff + ACK após SIFS); **RTS/CTS + NAV** combate a **estação escondida**.
- **DCF** (disputa) × **PCF** (polling pelo AP); coexistem no **superquadro** (CFP + CP).
- **SIFS < PIFS < DIFS < EIFS.**
- Quadro: FC, Duração, **A1–A3 (+A4)**, Seq, Corpo, FCS; **To DS/From DS** definem o significado dos endereços.
- **Beacon** (~100 ms): sincroniza, anuncia a rede, TIM. **Economia:** PS-Poll, APSD, WoWLAN; ad hoc usa ATIM.
- Entrada na rede: **varredura (passiva/ativa) → autenticação → associação**.
